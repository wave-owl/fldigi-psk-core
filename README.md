# fldigi-psk-core

A small C99 BPSK library for PSK31, PSK63 and PSK125. The receiver takes audio samples and
returns decided bits; the transmitter takes bits and returns audio or analytic IQ.

It is a C port of [wave-owl](https://github.com/wave-owl/wave-owl)'s Python port of the
fldigi 4.2.13 PSK receiver (`psk::rx_process`):

| Part | fldigi 4.2.13 source |
|------|----------------------|
| Complex NCO, fir1 low-pass + decimation to 16 samples per symbol | `src/psk/psk.cxx:2020-2044` |
| Filters per submode (raised cosine + PSKCore matched filter, Blackman sinc for PSK125) | `src/psk/psk.cxx:940-958`, `src/psk/pskcoeff.cxx:203-312` |
| Bit clock from the envelope (syncbuf early/late balance) | `src/psk/psk.cxx:2061-2158` |
| Differential phase decision, signal quality | `src/psk/psk.cxx:1490-1580` |
| AFC from the residual phase error (`phaseafc`) | `src/psk/psk.cxx:1442-1468` |

The transmitter (`src/psk_tx.c`, since 0.2.0) is ported from fldigi 4.2.13 `psk::tx_process`
directly:

| Part | fldigi 4.2.13 source |
|------|----------------------|
| `tx_init`: phase 0, previous symbol (1,0) | `src/psk/psk.cxx:196-234` |
| Symbol length and `dcdbits` per submode | `src/psk/psk.cxx:372-397` |
| Raised-cosine `tx_shape` | `src/psk/psk.cxx:1045-1052` |
| `tx_carriers` (one carrier, phase wrap, per-symbol `maxamp`), `sym_vec_pos` | `src/psk/psk.cxx:2196-2311` |
| `tx_bit` (BPSK: 1 keeps the phase, 0 reverses it) | `src/psk/psk.cxx:2324-2361` |
| Preamble (`dcdbits` reversals) and BPSK `tx_flush` | `src/psk/psk.cxx:2612-2620`, `:2535-2543` |

The library returns exactly the bit sequences, carrier frequencies and SNRs of the Python
reference on the golden data in `tests/golden/`, and the transmitter reproduces fldigi's own
TX output sample for sample. It is used by wave-owl as its native PSK core.

## Contract

Contract `psk-c1`, ABI 1 (`FPSK_CONTRACT`, `FPSK_ABI` in `include/fldigi_psk.h`).
`fpsk_version()` returns `"fldigi-psk-core <x.y.z> contract=psk-c1 abi=1 tx=1"`; callers check
this string when loading the shared library. The capability tag `tx=1` (since 0.2.0) marks the
additive transmitter API; the receiver API and its behaviour are unchanged.

## API

```c
#include "fldigi_psk.h"

fpsk_config cfg = {
    .sample_rate = 8000, .baud = 31.25, .center_hz = 1000,
    .afc = 1, .afc_range_hz = 0,   /* <= 0: one symbol rate */
};
fpsk_rx *rx = fpsk_rx_create(&cfg);           /* NULL on invalid config / OOM */
uint8_t bits[64];
size_t n = fpsk_rx_process(rx, audio, nsamples, bits, 64);
fpsk_rx_destroy(rx);
```

| Function | Purpose |
|----------|---------|
| `fpsk_version()` | Version and contract string |
| `fpsk_rx_create(cfg)` / `fpsk_rx_destroy(rx)` | Create / free a receiver; baud 31.25, 62.5 or 125 with `sample_rate / baud` = 256, 128 or 64 (8 kHz) |
| `fpsk_rx_reset(rx)` | Back to the initial state |
| `fpsk_rx_process(rx, x, n, bits, max_bits)` | Process `n` samples (doubles); writes at most `max_bits` bits (1 = no phase reversal, 0 = reversal) and returns the number decided (excess bits are counted but dropped); at most `n / (rate / baud / 16) + 2` bits per call |
| `fpsk_rx_set_freq(rx, hz)` | Retune the carrier and the AFC centre, keeping the receiver state |
| `fpsk_rx_freq_hz(rx)` | Current carrier frequency (moves with AFC) |
| `fpsk_rx_snr_db(rx)` | Phase-scatter SNR estimate (0 before 10 symbols) |
| `fpsk_rx_quality(rx)` | fldigi's `norm(quality)`: 1 for clean BPSK, near 0 for noise |
| `fpsk_rx_taps(rx, FPSK_FIR1 / FPSK_FIR2, out, max)` | The filter taps (65 for PSK31/63, 64 for PSK125) |

The input is processed in blocks of one symbol starting at `x[0]`, so an AFC correction
takes effect within a symbol. Without AFC the result does not depend on how the audio is
split into calls; with AFC it may (as in the reference implementation). Varicode decoding is
left to the caller.

### Transmitter

```c
fpsk_tx_config tcfg = { .rate = 48000, .baud = 31.25, .carrier_hz = 1000 };
fpsk_tx *tx = fpsk_tx_create(&tcfg);          /* NULL on invalid config / OOM */
size_t n = 0;
n += fpsk_tx_preamble(tx, re + n, im + n, max - n);
n += fpsk_tx_bits(tx, bits, nbits, re + n, im + n, max - n);  /* varicode bits */
n += fpsk_tx_postamble(tx, re + n, im + n, max - n);
fpsk_tx_destroy(tx);
```

| Function | Purpose |
|----------|---------|
| `fpsk_tx_create(cfg)` / `fpsk_tx_destroy(tx)` | Rate 8000 or 48000 Hz, baud 31.25, 62.5 or 125, `0 <= carrier_hz < rate / 2` |
| `fpsk_tx_reset(tx)` | fldigi `tx_init`: phase 0, previous symbol (1,0) |
| `fpsk_tx_symbol_len(tx)` / `fpsk_tx_preamble_symbols(tx)` | `rate / baud` samples; `dcdbits` 32, 64 or 128 |
| `fpsk_tx_preamble(tx, re, im, max)` | `dcdbits` phase reversals |
| `fpsk_tx_bits(tx, bits, n, re, im, max)` | One symbol per bit (nonzero = 1 = keep the phase, 0 = reverse) |
| `fpsk_tx_postamble(tx, re, im, max)` | `dcdbits` steady symbols, then `2048 * rate / 8000` zeros |

With `im == NULL` the output is fldigi's real audio, each symbol divided by its own peak. With
`im != NULL` it is the analytic signal `ival * e^{j phi}` of the same symbols (envelope peak 1,
no peak division, only positive frequencies). Each call writes whole symbols; if `max` is too
small (or `re` is NULL) it writes nothing, returns 0 and keeps the state, so an over can be
rendered in any number of calls with the same result. Varicode encoding (each codeword
followed by `00`) is left to the caller.

## Build

Plain `make`, C99, no dependencies besides `libm`:

```sh
make                          # static + shared library into build/
make test                     # build and run tests/test_psk and tests/test_psk_tx
make sanitize                 # the same tests under ASan + UBSan
make bench                    # CPU: 60 min of 8 kHz audio per submode, 120 s PSK31 TX over
make BUILD=/abs/dir shared    # out-of-tree shared library (used by wave-owl)
```

## Tests

`tests/test_psk <golden_dir>` checks the golden cases (bits exact, carrier frequency within
0.01 Hz, SNR within 0.01 dB), the filter taps per submode (within 1e-12), the version
string, chunk invariance on the clean vectors (one call vs. random call sizes of 1..4000
samples, AFC off and on), the per-call bound `n / (rate / baud / 16) + 2` on every golden
case fed in random call sizes, `max_bits` truncation, invalid configurations, reset and
`set_freq`.

The golden data (`tests/golden/`) is generated from a wave-owl checkout with
`tests/golden/make_golden.py /path/to/wave-owl` (wave-owl virtualenv): raw little-endian
`int16` (`.s16`, scaled by 1/32768) or `float64` (`.f64`) audio at 8 kHz, `expected.txt`
(`name submode center_hz afc chunk(0=none) freq_hz snr_db file nbits bits_hex`, bits packed
MSB first as `np.packbits`) and `taps_<submode>_fir1.txt` / `taps_<submode>_fir2.txt`.

`tests/test_psk_tx <golden_dir>` renders the three fldigi TX reference vectors in real mode
(8000 Hz, carrier 1500 Hz, scaled by `10^(-12/20)`, `lrint(x * 32767)`) and compares them with
fldigi's output: same length, at most 1 LSB difference (currently 0). It also checks at 48 kHz
that the IQ real part divided by each symbol's peak equals the real mode within 1e-12 and that
the envelope peak is 1, chunk invariance (bits split into calls of 1, 3, 7 and 64), invalid
configurations, symbol lengths and `dcdbits`, the "max too small" case and the version tag.
`tests/golden/tx/` (`<name>.s16` fldigi samples, `<name>.bits` varicode bits) is generated with
`tests/golden/make_tx_golden.py /path/to/wave-owl`.

## Notes

- Compiled with `-ffp-contract=off` (no implicit fused multiply-add) so that the arithmetic
  follows the reference order; sums and complex magnitudes reproduce numpy's pairwise sum
  and `abs()` bit for bit.
- Performance (`make bench`, Apple Silicon, `-O3`, 512-sample blocks, AFC on): about 0.6 s
  (PSK31), 0.9 s (PSK63) and 1.5 s (PSK125) CPU per hour of audio. Rendering a 120 s PSK31
  over as 48 kHz IQ takes about 0.05 s.
